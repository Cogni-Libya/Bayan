# Arabic Text Simplification: Datasets and Published Systems

Supports: Final Report 2.1 (Data Acquisition), 2.2 (Training Methodology), 3.3 (Modeling).

## 1. Parallel simplification data

| Resource | What it is | Size | Access | Use for Bayan |
|---|---|---|---|---|
| **SAMER Corpus** — Alhafni, Hazim, Piñeros Liberato, Al Khalil & Habash, LREC-COLING 2024. [arXiv:2404.18615](https://arxiv.org/abs/2404.18615) | 15 Arabic fiction novels (Hindawi catalog, mostly 1865–1955). Each text in 3 aligned versions: original (Level 5), **Level 4** (grades 6–8), **Level 3** (grades 4–5). | 159,265 words; 4,289 paragraphs; 20,603 punctuated fragments (~7.5 words each); 43.3% of fragments unchanged | Request form on the CAMeL Lab site; internal research and evaluation, no redistribution. Bayan has CAMeL Lab approval (2026-09-11). | The only native, human-written multi-level Arabic simplification set. Best candidate for a human-reference **test** set. The paper publishes **no model baselines**. |
| **ATSC** — Alshanqiti et al., *IJACSA* 14(2), 2023. [doi:10.14569/ijacsa.2023.01402101](https://doi.org/10.14569/ijacsa.2023.01402101) | Arabic articles (history, geography, health, education, technology) with human split-and-rephrase simplifications | 500 documents; 546 original sentences → 1,243 simplified sentences; ~17K words each side | Via the authors (TSimAr resources) | Syntactic split-and-rephrase data; small. |
| **Arabic EW-SEW and WikiLarge** — Al-Thanyyan & Azmi, *JKSU-CIS* 35(8), 101662, 2023. [doi:10.1016/j.jksuci.2023.101662](https://doi.org/10.1016/j.jksuci.2023.101662) | English Wikipedia → Simple English Wikipedia pairs translated to Arabic | EW-SEW 82,585 pairs; WikiLarge test 249 pairs | Per the authors | Machine-translated, not native Arabic simplification. |
| **Saaq al-Bambuu** — Khallaf, Sharoff & Soliman, WANLP 2022. [doi:10.18653/v1/2022.wanlp-1.5](https://doi.org/10.18653/v1/2022.wanlp-1.5) | Novel aligned with its simplified learner edition | 2,980 parallel sentences | Private (listed as such in MultiSim) | Not obtainable; cite as prior work only. |
| **DAASI** (tabsIT project) — local `capstone_data/tabsit/DAASI-parallel.xlsx`; GitHub `Huseen1141/tabsit` | Government / insurance form text → plain Arabic; target column labeled "SAMER Level 3". Per its annotation guidelines, **GPT-4o drafted each simplification and two annotators accepted, revised or rejected it**, with a third resolving disagreements. | 2,350 pairs (mostly short form phrases) | Data **CC0**; code under a non-commercial research license | Freely usable human-verified pairs in a different domain; also a working model of the "LLM draft + human verification" process Bayan needs for its test set. |
| **Baseet** — GitHub `raya-y/Baseet`; local `capstone_data/Baseet` | 34,294 source sentences (Bayyin + SAMER) × 3 levels, targets generated by Aya-8B | 102,882 generated targets; predictions of 5 models on Google Drive | No license file | Closest prior Arabic system; see `baseet_baseline_analysis.md` before reusing its numbers or its hybrid design. |

Not available, or not what they are often described as (checked 2026-09-17):
- **MultiSim** (GitHub `XenonMolecule/MultiSim`, HF `MichaelR207/MultiSim`) ships no Arabic data — its only
  Arabic entry, Saaq al-Bambuu, is private. There is **no Simple Arabic Wikipedia**.
- **ATSC** is downloadable from GitHub `AMahfodh/ArSummarizer`, path `TSimAr/resources/Simplification_Datasets(ATSC)`
  (no license file — ask the authors before redistributing).
- **Arabic EW-SEW / WikiLarge** repo (`SuhaSaleh/Arabic-EW-SEW-and-WikiLarge-datasets`) contains only
  ~4,000 / 400 / 50 EW-SEW lines and a small WikiLarge test file — not the paper's 82,585 pairs. No license file.
- **Al-Safy** (`laithjalamneh/Al-Safy-Arabic-Text-Simplification`, MIT) contains training code only; its
  "9,185 pairs" are 4,307 legal/news pairs expanded by synonym augmentation, and the data is not published.
- **mEdIT** (`grammarly/medit`, CC-BY-NC-4.0) has Arabic grammatical-error-correction rows but no Arabic
  simplification rows.

### Paraphrase corpora — useful for the equivalence judge, not as simplification data

| Resource | Labels | Use for Bayan |
|---|---|---|
| **ArPC** (`alaa-smt/ArPC`, local `capstone_data/ArPC`) — Arabic translation of MSRP | Train ≈ 567 paraphrase / 514 non-paraphrase; Test 61 / 189 | Labeled **negative** (non-equivalent) pairs to test whether Bayan's semantic-equivalence validator can say "no" — it currently cannot. |
| **APB** (`marwah2001/Arabic-Paraphrasing-Benchmark`, local `capstone_data/APB`) | 759 paraphrase / 251 non-paraphrase | Same use; small and hand-built. |
| iWAN Arabic Paraphrased Dataset (`iwan-rg/Arabic-Paraphrased-Dataset`), Arabic Quora Duplicates, XL-Sum Arabic | Paraphrase / duplicate / summary pairs | Not simplification; low priority. |
| Hadith CA→MSA (`ShathaTm/CA_MSA`, 250 pairs) | Classical → MSA | Out of scope: Bayan keeps scripture unchanged. |

## 3. Published simplification systems

| System | Approach | Reported results (as published) |
|---|---|---|
| **Al-Thanyyan & Azmi (2023)** — hybrid | Neural MT model + Arabic-BERT lexical simplification, and a hybrid of both | Hybrid on WikiLarge (249): **SARI 37.15, BLEU 55.68, BERTScore 86.7%** (0–100 scale) |
| **TSimAr** — Alshanqiti et al. (2023) | Seq2seq with FNet (Fourier-transform) layers, split-and-rephrase | ATSC: **SARI 0.73, BLEU 0.65, METEOR 0.68** (0–1 scale) |
| **ATSimST** — Alsughayyir & Alshanqiti, *IJAAS* 12(4), 71–78, 2025. [doi:10.21833/ijaas.2025.04.009](https://doi.org/10.21833/ijaas.2025.04.009) | Switch-Transformer seq2seq for split-and-rephrase; ATSC with a random 50/20/30 split | **SARI 0.81, BLEU 0.69, METEOR 0.72**, TER 0.93 (TSimAr best TER, 0.34). Run time: ATSimST 421 s, TSimAr 724 s, mBART 3,685 s; Arabic-T5-small fastest. Baselines included mT5-base, mBART-large-50, Arabic-T5-small, AraT5-base-title-generation. |
| **Baseet (2026)** — University of Jeddah graduation project | AraT5v2 / AraBART with level tokens on Aya-8B-generated targets; "hybrid" adds masked-LM word substitution | README: AraT5v2 SARI 43.84–46.13 (test split); hybrid 53.56–54.81 (computed on all rows, incl. training). Our re-scoring on the real test split: AraT5v2 51.5–53.7 vs. hybrid 50.1–51.3; copy-input 39.2–45.6. See `baseet_baseline_analysis.md`. |
| **Khallaf, Sharoff & Soliman (2022)** | (i) Arabic-BERT + fastText lexical pipeline; (ii) mT5 seq2seq; Saaq al-Bambuu data | BERTScore F1 **0.97** (lexical) and **0.70** (mT5). Manual error analysis: only **31 of 299** test sentences correctly simplified. SARI/BLEU were deliberately **not** reported. |
| **SalahEldin & Sabty (2023)** — ArabicNLP, pp. 418–422. [doi:10.18653/v1/2023.arabicnlp-1.35](https://doi.org/10.18653/v1/2023.arabicnlp-1.35) | Lexical simplification with word embeddings | — |
| **Nassiri et al. (2023)** — LNNS (Springer). [doi:10.1007/978-3-031-26254-8_84](https://doi.org/10.1007/978-3-031-26254-8_84) | Lexical simplification of Arabic educational texts, classification approach | — |
| **Hazim et al. (2022)** — EMNLP demos. [doi:10.18653/v1/2022.emnlp-demos.24](https://doi.org/10.18653/v1/2022.emnlp-demos.24) | Word-level readability visualization for assisted (human) simplification | — |

## 4. Closely related work worth knowing

| Work | Verified content | Why it matters |
|---|---|---|
| **AraT5-MSAizer** — Fares, OSACT @ LREC-COLING 2024, pp. 124–129. [doi:10.63317/26nxp6cqn8q2](https://doi.org/10.63317/26nxp6cqn8q2) | Fine-tunes AraT5v2 for dialect → MSA translation | Precedent for fine-tuning AraT5v2 on an Arabic-to-Arabic rewriting task. |
| **EhiMeNLP at TSAR 2025** — Miyata et al., pp. 217–222. [doi:10.18653/v1/2025.tsar-1.18](https://doi.org/10.18653/v1/2025.tsar-1.18) | **Won** the TSAR 2025 shared task on readability-controlled simplification: candidates from multiple LLMs with prompts, then readability-based filtering and ranking by semantic similarity to the source | Precedent for Bayan's generate-and-rerank data pipeline. The task was not Arabic; model names and candidate counts were not checked. |
| **BALSAM** — Al-Matham et al., ArabicNLP 2025. [arXiv:2507.22603](https://arxiv.org/abs/2507.22603) | Arabic LLM benchmark: 78 tasks, 14 categories, ~52K examples; includes a **Text Simplification** task (98 test / 41 dev in Phase 1) | Could provide extra Arabic simplification test items and LLM comparisons. |
| **RL for Catalan simplification** — Ayguadé Domingo, Bott & Saggion, 2026. [arXiv:2609.04823](https://arxiv.org/abs/2609.04823) | GRPO post-training of IberianLLM-7B on ASSET with a SARI-based reward plus a length penalty; improved on Catalan benchmarks, but cross-lingual transfer (translated ASSET) showed no significant out-of-domain gain | An idea for later, not evidence for Arabic. |
| **Can LLMs control readability? (Arabic)** — Rabih, Qwaider & Briscoe, READIxTSAR @ LREC 2026. [arXiv:2606.21981](https://arxiv.org/abs/2606.21981) | For CEFR-targeted Arabic generation, **unconstrained prompting gives weak level control**; CEFR-guided prompting **with lexical constraints** reached 0.99 agreement with predicted readability and 0.91 similarity to reference linguistic profiles | Put explicit lexical constraints (e.g. SAMER-lexicon levels) into Bayan's generator prompt instead of only "simplify to easy". |
| **Policy-based sentence simplification** — Wu, Arase & Nagata, 2025. [arXiv:2512.06228](https://arxiv.org/abs/2512.06228) | Uses LLM-as-a-judge to build policy-aligned training data with **no parallel corpus or human annotation**; small open models (Phi-3-mini-3.8B) surpassed GPT-4o on lexical-oriented simplification and matched it on full rewriting | Closest published precedent for Bayan's data pipeline; also shows the *policy* (lexical-only vs. full rewrite) should be chosen explicitly. |
| **Step-by-step proficiency-controlled simplification** — Zhang et al., Findings of EACL 2026. [arXiv:2602.07499](https://arxiv.org/abs/2602.07499) | LLMs are limited at simplifying **across large readability gaps**; decomposing into steps improves control, but meaning preservation during extensive simplification remains unsolved, and human annotators disagree on meaning-preservation judgments | Large jumps (hard → easy) are the riskiest; consider stepwise targets and budget for meaning checks. |
| **Taming CATS (control tokens)** — Hubarava & Gao, READIxTSAR @ LREC 2026. [ACL Anthology 2026.readi-1.3](https://aclanthology.org/2026.readi-1.3/) | Instruction fine-tuning with discrete control tokens learned readability control consistently (English; Llama/Mistral/Qwen 1–14B); small models were competitive; **the training-data distribution largely determines controllability** | Bayan's level tokens only work if training pairs actually differ across levels — Baseet's outputs often do not. |
| **LLMs across simplification tasks** — Qiang et al., 2025. [arXiv:2502.08281](https://arxiv.org/abs/2502.08281) | LLMs outperformed non-LLM methods on lexical, syntactic, sentence and document simplification, and often **exceeded the quality of human-annotated references** | Benchmark zero-shot LLMs against AraT5 honestly; reference-based scores can penalize outputs better than the references. |
| **Arabic GEC with synthetic data** — Dekmak, AUB thesis, 2026 ([scholarworks.aub.edu.lb](https://scholarworks.aub.edu.lb/items/4728dcd0-668f-419f-ba03-8c1749e69d6a)) | AraT5v2-base-1024 trained on ~650K distilled synthetic pairs reached 80.86 F0.5 on QALB; 3–14B LLMs underperformed specialized models, with the gap narrowing as scale grows; data quality was the main driver | The closest Arabic evidence that "AraT5v2 + LLM-distilled synthetic data" works for an Arabic rewriting task (grammar correction, not simplification). |
| **LLM data generation for low-resource languages** — Anikina et al., EMNLP 2025. [arXiv:2506.12158](https://arxiv.org/abs/2506.12158) | Across 11 languages, **target-language demonstrations plus LLM-based revision** gave the best synthetic data, narrowing the gap to real data to as little as ~5% in some settings | Add Arabic few-shot examples and a revision pass to the generator. |
| **YallaMorph** — Reda, Khalifa, Marzouk & Habash, 2026. [arXiv:2609.10153](https://arxiv.org/abs/2609.10153) | Benchmark for Arabic morphological generation in LLMs | Morphological errors in LLM-generated simplifications (title-level check). |
| **DSPy** — Khattab et al., 2023. [arXiv:2310.03714](https://arxiv.org/abs/2310.03714) | Framework for compiling LM pipelines against metrics | Used for Bayan's generator and equivalence validator. |

## 5. Corrections to earlier versions of these references

- SAMER is 15 novels with Levels 5 → 4 → 3; it is **not** "Saaq al-Bambuu" and has no "Full/Partial/Lexical" levels. No fine-tuned AraT5 results exist in the SAMER paper.
- The BAREC Shared Task winner is !MSA, not "GNNinjas". BAREC's authors do not include Alhafni.
- ATSC is 500 documents / 546 → 1,243 sentences, not "2,042 sentences".
- TSimAr is 2023 with SARI 0.73 (not "2025, SARI 39.8"); ATSimST scored SARI 0.81 (not "~0.75+" or "41.2"), and there is no "40% training-latency reduction" claim.
- Khallaf et al. reported no SARI or BLEU; any such numbers attributed to them are invented.
- HF IDs `aubmindlab/arat5-base`, `aubmindlab/arat5v2-base-1024` and `CAMeL-Lab/BAREC` do not exist; the model is `UBC-NLP/AraT5v2-base-1024`. GitHub `tareknaous/readme` is ReadMe++, not MultiSim.
